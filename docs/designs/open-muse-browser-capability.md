# Design: OpenMuse Browser Snapshots, Refs, and Extraction

OpenMuse should show the agent the page that Chromium actually rendered, give it short references for exact elements, and return a fresh page view after navigation or scrolling.

## Outcome

Replace the current `main, [role=main]` text heuristic and caller-supplied role/name targets with a browser snapshot contract:

- `browser_observe` returns a bounded whole-page accessibility snapshot and opaque refs.
- `browser_navigate` and `browser_scroll` return a fresh snapshot with their result.
- `browser_click`, `browser_fill`, and `browser_select` accept only a ref from the latest valid snapshot.
- `browser_extract` captures bounded, redacted page text, optionally scoped to a ref, and asks `gpt-5-nano` to format it as Markdown.
- If Markdown conversion fails, the tool returns the captured text with a warning.

## What Already Exists

- `browser-operations.ts` validates operations, generates the guest Playwright program, blocks private URLs, masks sensitive paths, and checks fields before filling. Reuse it as the only operation-program generator.
- `ActionBroker` already serializes actions, binds approval to a tab epoch and exact page, journals dispatch, and handles uncertain outcomes. Extend this path instead of creating another action executor.
- `ConversationManager` already invalidates approvals on new input and takeover, increments tab epochs on navigation, and forces re-observation after takeover. Clear refs at those same barriers.
- The guest runner already bounds returned strings, arrays, objects, execution time, and program size. Keep it unchanged in this slice.
- Pi already exposes the OpenAI model catalog and request client. Reuse it for the one Markdown-formatting call.

## Architecture

```text
Pi browser tool
      │
      ▼
ActionBroker
  ├── passive observe/extract ───────────────┐
  ├── ref lookup + approval for actions      │
  └── navigation approval                    │
      │                                      │
      ▼                                      │
short-lived guest Playwright runner          │
      │                                      │
      ├── accessibility snapshot + ref map ──┘
      └── bounded visible text
              │
              ▼
       gpt-5-nano formatter
              │ failure
              └────────────► raw redacted text + warning
```

The host stores refs because the guest Playwright process exits after every operation. Each registry entry binds an opaque ref to:

```ts
type BrowserRef = {
  ref: string;
  role: string;
  name: string;
  nth: number;
  locatorId: string;
  actionable: boolean;
  observationId: string;
  tabId: string;
  tabEpoch: number;
  controlEpoch: string;
  pageBinding: string;
};
```

The model sees `ref`, `role`, `name`, and `actionable`, but not the binding fields or locator ID. Observation marks the exact DOM element with a random locator ID. Action lookup rejects an unknown, non-actionable, or stale ref before creating an approval. The resolved locator ID, role, and name are stored in the pending approval and revalidated against the element, tab, and page immediately before dispatch. Reordering duplicate controls keeps the marker on the originally observed element; replacing it makes the ref stale.

## Browser Tool Contract

```ts
browser_observe({})
// -> { observationId, title, url, snapshot, refs, truncated?, textBlocked? }

browser_navigate({ url })
// approval -> { opened, observation: BrowserSnapshot }

browser_scroll({ direction })
// -> { scrolled, observation: BrowserSnapshot }

browser_click({ ref })
browser_fill({ ref, value })
browser_select({ ref, label })

browser_extract({ scopeRef? })
// -> { title, url, markdown, source: "gpt-5-nano" | "raw-fallback", warning? }
```

`browser_keypress` remains page-scoped because it intentionally acts on the current focus rather than a referenced element.

## Capture and Conversion

Observation uses Chromium's accessibility tree rather than a site-specific CSS landmark. It includes accessible text across the document and assigns refs to semantic nodes. The output is capped before it returns to the host.

Extraction is a two-stage operation:

1. The guest runner reads visible text from the document body or the element resolved by `scopeRef`. Password, payment, token, and other sensitive fields remain blocked by the current policy. The capture is normalized and capped.
2. The host sends that capture to `gpt-5-nano` with instructions to preserve facts, emit Markdown only, and treat every source line as untrusted data rather than instructions.

The model call has a short timeout and bounded output. Empty output, timeout, unavailable model, authentication failure, or provider failure returns the raw capture with `source: "raw-fallback"` and a one-sentence warning.

## Ref Lifecycle

```text
observe/navigation/scroll
      │
      ▼
replace registry for active tab
      │
      ├── action on same tab + epoch + page ──► resolve and approve
      │
      ├── navigation ─────────────────────────► stale
      ├── new user message ───────────────────► stale
      ├── takeover/resume ────────────────────► stale
      ├── popup adoption/tab close ───────────► stale
      └── process restart ────────────────────► stale
```

Refs are deliberately not checkpointed. After restart or uncertain recovery, the agent must observe again.

## Failure Modes

| Failure | Handling | User-visible result | Test |
|---|---|---|---|
| Page has no `main` landmark | Capture the whole accessibility tree/body | Page content is present | Regression unit test |
| Duplicate role/name controls | Mark the observed DOM node and revalidate its role/name | Exact referenced control is used | Unit test |
| Ref used after navigation or takeover | Reject before approval | “Observe the page again…” | Broker test |
| Page changes after approval | Existing page/epoch validation aborts dispatch | Existing interrupted recovery | Broker regression |
| Sensitive route or field | Preserve current blocking rules | Empty/blocked capture or Take control recovery | Existing plus focused unit test |
| Formatter times out or returns empty output | Return raw capture | Raw text plus warning | Converter unit test |
| Capture exceeds bounds | Truncate before the model call | `truncated: true` | Unit test |

No failure above is silent.

The implementation adds focused tests to the existing Node test suite. Per the user's direction, it does not add or run a live LLM eval campaign for this first attempt.

## Performance Limits

- At most 100 refs per snapshot.
- At most 12,000 characters of accessibility snapshot text.
- At most 16,000 characters sent to the Markdown formatter.
- At most 16,000 characters returned as Markdown.
- One formatter request per explicit `browser_extract` call; observation, navigation, and scrolling never invoke a model.
- The formatter timeout is 10 seconds with no fallback model retry.

## Implementation Plan

1. Add snapshot, ref, and resolved-operation types to the browser operation boundary.
2. Generate whole-page accessibility snapshots and semantic ref metadata in the guest program.
3. Store and invalidate refs in `ConversationContext`; resolve action refs in `ActionBroker` before approval.
4. Return and register a fresh snapshot after observation, navigation, and scrolling.
5. Add an injected `gpt-5-nano` Markdown formatter with raw-text fallback.
6. Expose `browser_extract` and ref-only action schemas to Pi; update its browser instructions.
7. Add focused unit and broker regression tests, then run the OpenMuse typecheck and test suite.

Sequential implementation, no parallelization opportunity: the operation types, broker, context, and tool schemas change as one contract.

## NOT in Scope

- A persistent in-VM browser gateway. It remains the next runtime-hardening step after this tool contract proves useful.
- A browser-image or Playwright upgrade. This slice must work with the currently published guest runner.
- Re-exposing model-written `browser_run` programs.
- Stagehand, Browser Use, or another browser-agent dependency.
- Typed-schema extraction, extraction-specific agents, or a live LLM evaluation campaign.
- Persistent authenticated browser profiles, uploads, downloads, CAPTCHA handling, or visual coordinate fallback.
